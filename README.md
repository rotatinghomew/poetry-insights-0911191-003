# 唐诗工坊满额下的真实需求与增场评估

本项目保存诗词工坊报名和场次安排的合成资料，并提供一个仅依赖 Python 标准库
（3.11+）的工具链：把预约流水重建成可审计的需求观测，估计被名额截断的潜在需求，
再对下月几套可执行的增场方案做**联合**模拟评估。

## 数据

- `data/requests.csv`：申请人及时段偏好顺序（`rank=1` 为首选，`rank>1` 仅为替代证据）。
- `data/booking_events.csv`：确认、候补邀请、接受、拒绝、撤销、售罄浏览、闭馆、
  名额变动、出席/缺席事件；可选 `recorded_at`（补登时点）与 `week`（匿名供给事件归属）列。
- `data/sessions.csv`：工坊、讲师、场地和最低开课人数；可选 `closed` 列标记闭馆。
- `example_data/`：由 `tools/make_synthetic_data.py` 生成的 6 周多时段合成资料，
  覆盖满额、匿名浏览、转场、回流、重复邀请、闭馆、零名额、事后补登等全部情形。
- `example_data/plan_*.json`：三套候选方案（可行加开场、含节庆新品类、含资源冲突）。

资料使用 UTF-8 CSV，空字段表示记录未提供，而不是“没有发生”。

## 方法论与口径（先读这里）

### 1. 五类信号严格区分，转场不算新增

`workshop/reconstruct.py` 逐周逐时段重建事件流：

| 信号 | 处理 |
| --- | --- |
| 有凭据的首次需求 | `rank=1` 的去重申请人，是独立需求的唯一计数基础 |
| 改报替代场 | `rank>1` 偏好或候补后接受另一场，只进偏好替代模型，不计入任何时段新增 |
| 退订回流 | 撤销 A 后同周确认/接受 B，记 A→B 回流，B 的独立需求不增加 |
| 重复通知 | 同一申请人多次候补邀请只计一次人，重复次数单列 |
| 没有观测的需求 | 匿名售罄浏览只作“存在未知需求”的证据，不能计入人数，更不能当零需求 |

**闭馆 ≠ 名额设零**：闭馆是“无观测”（不进似然）；名额设零是右删失观测
（真实需求 ≥ 已观测人数）。满额后的事件携带的 `capacity=0` 是剩余名额而非供给名额，
只有显式“名额变动”事件的 0 才代表名额设零。

### 2. 潜在需求估计：删失泊松 + 经验贝叶斯

`workshop/demand.py` 把每个 slot-week 视为一个暴露单位：

- 未删失周贡献完整到达数；满额/零名额周用 EM 不动点按
  `E[D | D ≥ c] = λ·P(D≥c-1)/P(D≥c)` 填补；
- Gamma 共轭先验做跨时段经验贝叶斯收缩，输出点估计与 90% 可信区间；
- 证据分级：A（≥3 个未删失周，可直接排期）、B（样本/删失有限，区间宽）、
  C（无未删失观测、完全无历史，或节庆/新品类标签——只能先小范围试开并显式声明假设）。

### 3. 方案评估是联合问题，不能逐场相加

`workshop/planning.py` 在每轮蒙特卡洛里生成整盘申请人，再按各自偏好序做联合分配：

- 同一申请人只服务一次；新增场从旧场分流，旧场也承接新场满额后的人；
- 同一批随机数同时跑“只有旧场”的基线，两盘相减得到**净新增服务**与**挤出**；
- 硬约束先拦截：讲师/教室同时段冲突、最低开课人数高于名额、未知时段未声明；
- 最低开课人数不足的场次取消并重新安置其入座者，报告取消率与达标概率；
- C 级时段若无显式 `demand_assumptions`，只报证据缺口、不产出排期数字；
- 输出每场预计入座/到场/被拒、首选→入座替代矩阵、旧场→新场分流、资源冲突清单。

### 4. 点-in-time 回测，禁止事后信息泄漏

`workshop/backtest.py` 只用 `as_of` 时点可见的记录做预测：`recorded_at` 晚于
截止点的补登回应被剔除，出席/缺席事件永不进入预测输入（只用于实际值对照）。
评估周若满额，实际值只有下界，按区间下界相容性打分。未办过的方案不能回测，
只能报估计与假设。

## 命令行用法

隔离模式启动器（`-I` 防止从不信任数据目录加载模块）：

```bash
python3 -I run.py classify --data-dir example_data          # 需求分类与事件审计
python3 -I run.py demand   --data-dir example_data          # 潜在需求估计+证据分级
python3 -I run.py plans    --data-dir example_data \
    --plan-dir example_data --runs 1000                     # 联合模拟评估各方案
python3 -I run.py backtest --data-dir example_data --as-of 299
```

方案 JSON 的关键字段：`existing`/`added` 场次、`acceptable_slots`（可承接哪些
时段的需求）、`minimum`、`tags`（如 `节庆`/`新品类`）、`demand_assumptions`
（C 级时段的显式需求假设）、`show_rates`（分时段到场率）。

## 验证

```bash
python3 -I run_tests.py
# 或：python3 -m unittest discover -s tests -v
```

37 个测试覆盖：转场/回流/重复邀请/匿名满额的分类口径、闭馆与零名额的区分、
删失 EM 的数学性质、经验贝叶斯分级、联合分流与挤出、最低开课取消、
硬约束冲突、C 级证据缺口、回测补登泄漏与出席隔离。

## 代码结构

```
workshop/
  dataio.py       CSV/JSON 加载（可选列、空字段语义）
  reconstruct.py  事件流重建与五类需求分类
  demand.py       删失泊松 EM、Gamma 经验贝叶斯、区间与证据分级
  prefs.py        偏好序与替代行为模型
  planning.py     硬约束检查 + 联合蒙特卡洛评估
  backtest.py     点-in-time 回测
  cli.py          四个子命令
tools/make_synthetic_data.py  确定性合成资料生成器
```
